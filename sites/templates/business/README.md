# Шаблоны сайтов для бизнеса

Пять самостоятельных шаблонов на общем ядре: event-агентство, детейлинг, автосервис, косметология, салон красоты.
Стек — HTML, CSS, JavaScript без сборки и Node.js-сервер без зависимостей.
Все данные бизнеса лежат в `config.js` каждой папки. Вёрстку и обработчики для замены данных менять не нужно.

Шаблоны основаны на `sites/niches/`. Примеры в `sites/niches/` не изменены.

## Термины

| Термин | Значение |
|---|---|
| Шаблон | Запускаемый сайт с заменяемыми данными. |
| Демонстрационные данные | Примеры, которые не описывают реальный бизнес. Помечены `demo: true`. |
| Заявка | Запрос клиента, который требует ответа бизнеса. Все формы шаблонов отправляют заявки. |
| Бронирование | Подтверждённый резерв ресурса на интервал. Шаблоны бронирование не делают. |
| Конфигурация | Файл `config.js` с данными и настройками одного шаблона. |
| Референс | Источник отдельных дизайнерских приёмов. См. `REFERENCES.md`. |

## Запуск

Требование: Node.js 18 или новее. Установка пакетов не нужна.

1. Откройте терминал в корне репозитория.
2. Выполните команду:

```bash
node sites/templates/business/server/server.mjs
```

3. Откройте в браузере `http://localhost:8090/`.

Локальные адреса:

| Адрес | Что открывается |
|---|---|
| `http://localhost:8090/` | Оглавление шаблонов |
| `http://localhost:8090/event/` | Event-агентство |
| `http://localhost:8090/detailing/` | Детейлинг-студия |
| `http://localhost:8090/auto/` | Автосервис |
| `http://localhost:8090/cosmetology/` | Косметология |
| `http://localhost:8090/beauty/` | Салон красоты |
| `http://localhost:8090/crm/` | CRM-панель заявок (нужен `ADMIN_TOKEN`) |

Просмотр без сервера тоже работает: откройте `<ниша>/index.html` двойным щелчком.
В этом случае сайт работает только в режиме `demo`.

## Режимы

Режим задаёт поле `meta.mode` в `config.js`.

| Режим | Куда уходит заявка | Что видит посетитель |
|---|---|---|
| `demo` (по умолчанию) | Только в `localStorage` этого браузера. Наружу ничего не уходит. | Плашка «Демонстрационный шаблон», метки «пример», сообщение «Демо-заявка сохранена на этом устройстве». Страница закрыта от индексации (`noindex`). |
| `production` | На сервер `integrations.endpoint`. Сервер сохраняет заявку на диск и только потом отвечает «принято». | Нет демо-меток. Метаданные и `canonical` из `seo`. |

Если в режиме `production` конфигурация не прошла проверку, сайт показывает предупреждение и отключает формы.

Проверка для разработчика (действует только на `localhost`):

- `?mode=server-test` — демо-данные, но заявка уходит на локальный сервер. Сервер помечает её «тест» и не отправляет уведомления.
- `?mode=production` — рабочий режим с проверкой конфигурации.

## Проверка конфигурации перед публикацией

Выполните команду из корня репозитория:

```bash
node sites/templates/business/_shared/config-check.js
```

Скрипт проверяет все шаблоны по правилам `production`: контакты, адрес приёма заявок, юридические данные, цены, изображения, оставшиеся `demo: true` и плейсхолдеры `[В СКОБКАХ]`.
Код выхода `1` означает, что есть ошибки. Чтобы проверить один шаблон, добавьте имя папки: `... config-check.js beauty`.

## Сервер и CRM

1. Скопируйте `server/.env.example` в `server/.env`.
2. Задайте `ADMIN_TOKEN` — длинную случайную строку.
3. Перезапустите сервер.
4. Откройте `/crm/` и введите токен.

Без `ADMIN_TOKEN` CRM-панель закрыта: сервер отвечает `401` на запросы заявок и файлов.
Секреты Telegram, Bitrix24 и amoCRM храните только в `server/.env`. Не кладите их в `config.js`.

Что делает сервер (`server/server.mjs`):

- читает `config.js` каждой папки при старте: список сайтов, префиксы номеров, режим;
- принимает `POST /api/lead`, проверяет поля и согласие, ограничивает частоту (8 заявок за 10 минут с одного IP);
- сохраняет заявку в `server/data/leads.json`, вложения — в `server/data/uploads/<номер>/`;
- отправляет уведомления в Telegram и CRM только для сайтов в режиме `production` и только если заданы ключи;
- записывает результат доставки в поле `delivery` заявки. CRM-панель показывает его отдельно от статуса заявки.

Если внешняя интеграция не настроена, заявка всё равно сохраняется на сервере. Поле `delivery` при этом равно `off`.

Проверка API (нужен запущенный сервер):

```bash
node sites/templates/business/server/api-check.mjs http://localhost:8090 <ADMIN_TOKEN>
```

Скрипт создаёт тестовые заявки. Запускайте его только на локальном сервере.

## Структура

```
sites/templates/business/
  README.md          этот файл
  REFERENCES.md      проверенные референсы и адаптация приёмов
  REUSE_MAP.md       что взято из базы и что изменено
  QA.md              результаты проверки и ограничения
  index.html         оглавление
  _shared/
    core.js          ядро (из sites/niches): скролл, модальные окна, формы, заявки
    core.css         базовые стили и общие элементы шаблонов
    site.js          вывод данных из config.js: цены, изображения, контакты, мастер шагов, cookie
    config-check.js  проверка конфигурации (браузер и Node)
    legal.js/.css    юридические страницы из config.legal
    components/      виджет fb-cookie-consent (копия из sites/components с доработками)
    fonts/           локальные шрифты (OFL)
    vendor/          Lenis и anime.js (MIT)
  server/            server.mjs, api-check.mjs, .env.example
  crm/               CRM-панель
  event/ detailing/ auto/ cosmetology/ beauty/
    index.html style.css app.js config.js README.md CONTENT_CHECKLIST.md img/ legal/
```

Порядок подключения скриптов в `index.html` ниши: `config.js` → `vendor/*` → `core.js` → `config-check.js` → `fb-cookie-consent.js` → `site.js` → `app.js`.
Ядро само собирает прежний объект `window.SITE` из `window.SITE_CONFIG`, поэтому контракт `sites/niches` сохранён.

## Общая схема `config.js`

У всех шаблонов общие группы. Поля конкретной ниши описаны в README её папки.

| Группа | Поля | Назначение |
|---|---|---|
| `meta` | `mode`, `site`, `prefix`, `lang`, `timezone` | Режим; уникальный код сайта (латиница); префикс номера заявки (2–4 заглавные буквы); язык; часовой пояс бизнеса. |
| `brand` | `name`, `logoText`, `logo`, `description`, `colors`, `fonts` | Название; текст логотипа; id картинки-логотипа в `assets`; описание; `colors.accent` меняет акцент; `fonts.heading` и `fonts.body` меняют семейства. |
| `contacts` | `phone`, `email`, `telegram`, `city`, `address`, `hours[]`, `map.url` | Пустое поле скрывает кнопку и строку. Телефон — `+7 (XXX) XXX-XX-XX`, Telegram — ник без `@`. |
| `hero` | `eyebrow`, `title`, `text`, `image`, `cta.label`, `cta.target` | Первый экран. `image` — id из `assets`, `cta.target` — id блока. |
| `services` | `id`, `name`, `price`, `duration`, … | Услуги с числовыми ценами и длительностью. `id` стабильные: на них ссылаются расчёты и заявки. |
| `team` | `id`, `name`, `role`, `services[]`, `photo` | Специалисты. Пустое `name` — выводится роль. Фото — только реальных сотрудников с их согласия. |
| `portfolio` | `id`, `title`, `image`, категория | Работы для галереи с фильтром. |
| `reviews` | `text`, `author`, `source`, `url`, `demo` | Пустой список скрывает блок. `demo: true` добавляет метку «Пример отзыва». |
| `faq` | `q`, `a` | Вопросы и ответы. |
| `booking` | `mode`, `dayParts`, `successTitle`, `successText` | `mode: 'request'` — заявка на запись. Время — «Желаемое время», без обещания свободного окна. |
| `pricing` | `note`, `demo` + поля ниши | Пояснение к расчёту и параметры калькулятора. |
| `integrations` | `endpoint`, `channels`, `analytics.yandexMetrika` | Адрес приёма заявок; какие способы связи показывать; счётчик аналитики. Счётчик запускается только после согласия на аналитические cookie. |
| `legal` | `operator`, `inn`, `ogrn`, `address`, `email`, `phone`, `site`, `effectiveDate`, `dataCollected[]`, `processors[]`, `approved`, `docs` | Реквизиты для подвала и юридических страниц. `approved: true` ставит владелец после проверки текстов. `docs.privacy` и др. заменяют шаблонный текст утверждённым. |
| `features` | флаги блоков | `false` скрывает блок и его пункт меню. |
| `seo` | `title`, `description`, `image`, `canonical` | Метаданные для `production`. В `demo` страница закрыта от индексации. |
| `assets` | `src`, `width`, `height`, `alt`, `role`, `source`, `author`, `license` | Каждое изображение с источником и лицензией. Нет файла — выводится нейтральная заглушка. |

### Цена

Цена — объект, а не строка. Число хранится отдельно от подписи.

| `type` | Поля | Вывод |
|---|---|---|
| `fixed` | `value` | `2 400 ₽` |
| `from` | `value` | `от 2 400 ₽` |
| `range` | `min`, `max` | `4 500–8 000 ₽` |
| `request` | — | `По запросу` |

Если цена неизвестна, укажите `{ type: 'request' }`. Не ставьте `0`: проверка конфигурации отклонит нулевую цену.
Если объекта цены нет, сайт выводит «Стоимость уточняется».

## Как адаптировать шаблон под бизнес

1. Скопируйте папку ниши и `_shared/`, `server/`, `crm/`.
2. Заполните поля из `CONTENT_CHECKLIST.md` ниши в `config.js`.
3. Замените фото в `img/` и записи в `assets`.
4. Удалите `demo: true` у всех записей, которые описывают реальный бизнес.
5. Проверьте тексты юридических страниц с юристом. После проверки поставьте `legal.approved: true`.
6. Поставьте `meta.mode: 'production'`.
7. Выполните `config-check.js`. Исправьте все ошибки.
8. Задайте `ADMIN_TOKEN` и, если нужно, ключи Telegram или CRM в `server/.env`.

## Ограничения

- Шаблоны не делают бронирование. `/api/busy` из `sites/niches` не перенесён: он не резервирует интервалы. Все формы — заявки, «Запись требует подтверждения».
- Контент выводится скриптом из `config.js`. Поисковики, которые не выполняют JavaScript, увидят пустые блоки. Для SEO с такими поисковиками нужен предварительный рендер.
- Юридические страницы — шаблоны на основе `sites/legal/`. Они не подтверждают соответствие всем требованиям закона.
- Демо-фото — стоковые CC0, а не работы бизнеса. Источники — в `img/CREDITS.md` каждой ниши.
- Подробные результаты проверки — в `QA.md`.
